# H-GAME 补充实验设计与验证说明

本模块依据截图 E1–E6 建立可复现的补充实验。审阅文档仅作为问题与比较要求的依据，不把其中的建议或原稿结论当作事实。**输入为受控合成算例，尚未构成真实城市或 Unreal 执行验证。**

## 运行与输出

在工作区根目录依次执行：

```powershell
python supplementary_experiments/run_experiments.py
python supplementary_experiments/verify_results.py
python -m unittest discover -s supplementary_experiments -p test_experiments.py -v
python supplementary_experiments/plot_results.py
```

已验证环境：Python 3.11.2、NumPy 2.3.5、SciPy 1.17.1；绘图使用 Matplotlib 3.10.8。未修改原求解器、UE配置或原始数据。

## 模型、单位及适用边界

六个1小时停车时段结束后，车辆在第6小时出发，要求第7小时前到达。每辆车必须选择一个路径及一个允许的充电时段，完成一次任务；不允许弃单。基准含8辆车、2条候选路径，初始与末端电量均20 kWh，电池40 kWh，充电效率0.9，单车功率上限6 kW，站点功率上限20 kW。单时段长度固定为1小时，因此时段购电kWh与该时段平均功率kW数值相同；不将其推广到其他采样间隔。

车辆基础耗电从[2.4,3.4] kWh均匀生成，停车起始时段从0、1、2中抽取，窗口默认4小时。外部购电价为[0.85,1.10,0.75,0.35,0.40,0.55]元/kWh，固定零售价在此基础上加0.25元/kWh。

路径r的耗电为基础耗电×(1+0.12r)，时间为0.4+0.025r+拥堵参数×(车辆数/8)²/(r+1)小时。拥堵是外生情景参数，不根据实际路径流量更新。更快路径可能消耗更多电，这是显式设定的机制，不是经验估计结论。所有充电发生在出行前，不包含途中充电、连续交通演化、内生排队或多站选择。

每个方案满足：

- 购电=(末端电量−初始电量+行驶耗电)/效率，且非负；不允许V2G或主动放电。
- 充电后电量不超过电池容量，行驶后恰好满足末端要求。
- 充电须在停车窗口和出发前完成；各小时总功率不超站点上限。
- 到达时间不晚于任务截止时间；每辆车恰好选择一个方案。

目标为20元/小时×出行时间+用户购电支出。各组均求解同一个集中整数规划的不同可行集限制。这是机制与边界算例，不是新算法、MNL随机均衡或交通容量反馈的证明。

## E1：固定价格的完整四组对照

基线固定路径0和最早停车时段；仅路径放开路径；仅充电放开充电时段；联合同时放开。任务、车辆、初始与末端电量、候选集、外部购电价格、固定零售价及物理约束一致。零售价与外部购电价并非同一条曲线，而是两个实验组之间各自保持一致。

报告服务完成率、迟到、出行时间、行驶耗电、购电量、峰值、用户费用、利润、资源成本和排放。联合可行集包含其他组，因此其最小用户目标值不会更差；不能由此证明算法新颖或所有物理指标均更好。独立审计逐组检查输入一致和可行集嵌套应有的性质。

## E2：价格反馈的增量比较

对联合组比较固定价格与3条有限候选零售价格；每条候选都重新求集中调度，以运营利润选择最佳候选。外部购电价格、任务与物理边界不变。候选含原固定价格；利润相同时取候选列表中先出现者。下层多最优解由固定版本求解器返回，未实现乐观或悲观双层择优；跨求解器版本可能存在不同的等价计划。

用户支出=零售价×购电量；运营利润=用户支出−外部购电成本；资源成本=时间价值+外部购电成本。费用是内部转移，不自动等于资源损失。有限候选搜索不是连续最优定价、分散用户最佳响应或Stackelberg均衡证明。保留每条候选结果，不只显示获选方案。

## E3：能量、服务和碳闭合

逐车与整体核验初始电量+效率×购电−行驶耗电−末端电量=0，损耗=(1−效率)×购电，并核对功率、窗口、电池上界和服务完成。排放仅为购电×0.5703 kg/kWh，不再叠加行驶耗电排放。该固定因子是算例参数，不声称是当前城市核定值；纯移时不能自动节电减排。

可行方案完成率为100%是硬约束的结果，不是外部实测成功率。不可行组没有可执行方案，完成率留空，不能伪填为0%或100%。

## E4：小规模正确性与边界

9类两车算例分别以整数规划和穷举求解：基本两路径、无价差、无充电灵活性、无拥堵、无收益控制、站点容量为0、充电功率为0、电池上界不足、末端要求改变。比较可行状态和最优目标；不可行算例不伪填目标差为0。

另有不导入主求解器的 verify_results.py：从manifest的原始任务重建候选方案，独立穷举全部两车输入、重新判定全部不可行设置，逐条核对导出计划、台账和经济指标。测试还用72个三车组合比较整数规划与此独立穷举器。

无收益控制同时取消路径选择、充电灵活性和价差，四组目标与排放应相同。单独无拥堵不等于无充电收益；单独无价差不等于无路径时间收益，不能混为一种边界。

## E5：代表条件与输入不确定性

9类情景为参考、无拥堵、高拥堵、稀缺充电、容量紧约束、充电充裕、短停车窗口、单路径和三路径。各使用10个种子：17、29、43、61、79、97、113、131、151、173；每个种子完整比较四组。随机性仅来自车辆耗电和停车起始时段；不宣称覆盖真实需求分布或模型误差。

分别报告仅路径、仅充电、联合相对基线的资源成本均值及观察最小最大值、购电变化和用户成本改善比例。统计以种子为配对单位，不把车辆或重复解当独立重复。最小最大值不是置信区间；10个种子属于受控敏感性检验，不支撑普遍效应推断。

将“仅基线不可行”“仅处理组不可行”“两组均不可行”和“求解器异常”分开。只在两组均可行时计算成本效应，因此均值是条件效应，有可行性筛选边界；基线不可行而联合可行时应报告可行性恢复，不能报告无限节约。

## 验证层次与仍需的数据

已验证：主算例、全部导出数据的独立物理与经济核算、87个不可行结果、9组两车穷举比较、72个额外三车穷举组合，以及两次完整运行的逐字节一致性。测试还主动修改负荷与利润，确认审计能检出；求解超时被保留为solver_limit，不能误报infeasible。

**E6尚未开展。** 2026-11-03源码复查：原求解器的OD解析已支持X=… Y=…和逗号坐标，且已使用固定点残差；原先的解析接口提示已过时。最低SOC反推需求仍不能代替完整任务能量账。新的独立受控算例与审计见工作区 `experiments/README.md`，其中的假设任务不等于原场景已具备完整任务数据。

要回到论文原场景，仍需统一任务ID、出发与截止时间、真实停车窗口、初始/末端电量要求、充电站容量与外部购电价。执行层需独立记录到达、排队、SOC轨迹和站点冲突，逐车比较计划与观测。缺少这些数据时仅称三维回放展示。原MNL/MSA收敛残差、真实行为有效性和Unreal执行一致性不在本轮通过验证的范围内。

可将此模块作为明确标注的受控机制补充；不能直接用其数值填入原论文真实场景表格，或据此保留普遍节能、减排和均衡已验证的主张。
